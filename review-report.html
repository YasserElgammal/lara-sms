مراجعة فنية لحزمة Lara SMS

تصحيح التقرير السابق

الاستثناءات SmsException وRetryableException وNonRetryableException كانت موجودة بالفعل. المشكلة كانت تحويلها إلى نص داخل البوابات والمدير ثم اتخاذ قرار fallback بمطابقة النص.

التحديث المنفذ

أضيف الحقل retryable إلى SmsResult للحفاظ على التصنيف: true للأخطاء القابلة لإعادة المحاولة، false للأخطاء الدائمة، وnull للأخطاء غير المصنفة. لم تعد قرارات المدير تعتمد على نص الخطأ.

FAIL_FAST يستمر فقط بعد فشل مصنف بأنه قابل لإعادة المحاولة. TRY_ALL يستمر بعد أي فشل. يعيد HTTP محاولة 429 و5xx ضمن العدد والفاصل المحددين؛ العدد يشمل المحاولة الأولى.

أضيف InvalidConfigurationException والتحقق من بنية الإعدادات وخيارات HTTP وأسماء البوابات. تستخدم فحوص بيانات الاعتماد الموجودة تصنيف الخطأ الدائم.

أعلنت متطلبات التشغيل PHP ^8.2 وIlluminate ^12.0. أضيفت اختبارات PHPUnit/Testbench للنجاح وإعادة المحاولة وfallback وFAIL_FAST والإعدادات والطوابير.

أضيف SendSms وBuilder::queue. للمهمة محاولة واحدة على مستوى الطابور، ويصل فشل الإرسال إلى العامل عبر استثناء. تستمر محاولات HTTP والبوابات داخل هذه المحاولة.

الحدود والعمل المتبقي

أخطاء الاتصال لا تعاد تلقائياً في HTTP لأن انتهاء المهلة قد يحدث بعد قبول الرسالة. أخطاء المزود داخل استجابة HTTP ناجحة تبقى غير مصنفة ما لم تصنفها البوابة صراحة.

لا يوجد ضمان للإرسال مرة واحدة. إعادة محاولة 5xx أو TRY_ALL أو إعادة تشغيل مهمة فاشلة يدوياً قد تسبب التكرار. يجب ضبط مهلة العامل وretry_after وفق المدة الكاملة للمحاولات. يشرح README طريقة الاستخدام والقيود.

نجحت الاختبارات المحلية باستخدام HTTP وهمي. تعذر تحديث composer.lock بسبب تعذر الاتصال بالوكيل الشبكي. ما زال مطلوباً توسيع اختبارات كل مزود والتحقق الدولي من الأرقام .
